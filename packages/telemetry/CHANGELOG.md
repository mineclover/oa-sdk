# @oa-sdk/telemetry

## 0.2.0

### Minor Changes

- 974aa04: Replace the reversible DPM pseudonymization with keyed HMAC-SHA-256 tokens and make the XState inspector safe to attach. Review the items marked **behavior change** when upgrading.

  - **Behavior change:** `createDpmTelemetryAdapter` tokens are `dpm_tok_<entity>_<32 hex>`, the first 128 bits of an HMAC-SHA-256 of the value, instead of an 8-hex FNV-1a hash with a public default salt that could be reversed or forged by dictionary. There is no default key: without `tokenKey` (`string | Uint8Array`) each adapter instance draws a random key, so pass one to correlate tokens across instances. An empty `tokenKey`, or pseudonymizing without `tokenKey` or `customTokenizer` on a runtime without `crypto.getRandomValues`, throws the new `TelemetryConfigError`.
  - **Behavior change:** the token namespace is the identifier's entity kind (`DEFAULT_PII_KEYS`, or the new `piiKeys` option) instead of the event's symbol domain, so one user keeps one token across domains; the `namespace` argument of `sanitize` no longer affects tokens. `masked` masks identifier keys with `***MASKED***` instead of passing them through. Identifier keys and `sensitiveKeys` match regardless of case, `-` and `_`, numeric identifiers are protected too, and cyclic, deeply nested and non-plain values become `[Circular]`, `[MaxDepth]` and `[ClassName]` instead of failing the send. `DEFAULT_SENSITIVE_KEYS` (now with `apikey`) and `DEFAULT_PII_KEYS` are exported.
  - The XState inspector never throws into XState and never subscribes to actors. An unregistered symbol is rejected only under `strictSymbols` and reported through the new `onError` option. Machine errors are dispatched once per actor, envelopes get `actorId` and `stateNode` from the event's `actorRef`/`sourceRef`, spans are tracked per actor reference, the raw global identity `userId` is replaced by its pseudonym, and the context gains `actorSessionId`.
  - **Behavior change (types):** `GtmDispatcherOptions.dataLayer` is `GtmDataLayerLike`, the Sentry client uses `SentryLikeScope`, and `OtelLikeSpan`/`OtelLikeTracer` take `OtelAttributes`/`OtelException`, so a real `@opentelemetry/api` `Tracer` and `Span` type-check. The OTel dispatcher gains a `getActiveSpan` option and falls back to the actor instance's span, so it records events with a real tracer. `CreateEnvelopeOptions.context` is `TelemetryContextInput`, and an explicit `undefined` no longer erases defaults such as `traceId`.
  - Payload fields can no longer override the reserved GTM `dataLayer` keys or the Sentry breadcrumb context keys. The composite dispatcher starts a span on every span-capable child, isolating failures, and returns `cspan_<n>` ids.
