"@oa-sdk/webmcp-peer": minor
---

The relay protocol spec (`docs/internal/webmcp-relay-protocol.md`) is now the single source of the WebMCP relay protocol, and a test checks it against the package (relay protocol spec O-59, O-60). No wire behavior changes in this step.

- The README, the api-index entry, the relay guide, the concepts page and the security notes summarize the wire rules and link to the spec instead of keeping rules of their own. Statements that contradicted the code are corrected: the relay checks the Host of a loopback relay; a closed provider socket ends the room's pending agent requests with `PROVIDER_DISCONNECTED` while the agents stay connected (also in the provider's source comments); a full queue closes a socket only when no write completes for 30 s after a refused frame; `clientLabel` and `alias` are cut to 256 code points; the provider works out `isError` of a host `CallToolResult` again; the AI run ledger exists only once a host sets one; the agent client checks the relay's catalog hash; -32027 is reserved; the client's request limit and the provider's catalog limit; the 256 KiB message limit in an earlier changeset; and the guide no longer mixes the `@oa-sdk/peer-server` relay's `409 ROOM_BUSY` with this relay's `409 INVITE_TOKEN_CONSUMED`. The security notes gain a webmcp-peer section.
- New `test/protocol-spec.test.ts` reads the spec in its own format and fails when a requirement ID is defined twice or referenced but undefined, a requirement states no evidence or a malformed one, a cited source line is missing or blank, a cited test file or test title does not exist, the limits table disagrees with an exported constant or leaves out a limit the `./config` tier exports, the close code table disagrees with `WEBMCP_CLOSE_CODES`, the error class table disagrees with the relay's error codes, or a document linking to the spec cites an undefined requirement ID.
- Regression tests now cover the requirements that had none, among them a duplicate request id on one socket, the formats of issued ids and tokens, the floor of `publishRateLimitMax`, the sweep timer, the request timeout, an id that `JSON.parse` reads as `Infinity`, a provider frame that grows when the relay writes it again, request-target normalization, node:http's header limit, the provider's keepalive, `ready` wait, ICE wait, descriptor checks and expiry timer, and the AI run ledger's replay.
- `PACKAGE_VERSION`, which the agent client sends as `clientInfo.version` and in its `user-agent`, is documented as having to equal the package version, and a test now fails when a version bump changes one without the other.
- Spec corrections found while adding tests: the provider's `PEER_SESSION_SUPERSEDED` and `OUTCOME_UNKNOWN` answers never reach the wire, since the channel that would carry them is closed first; the spec now calls them defensive and lists the question as open (O-68).
