A room's expiry is now one signal on every surface, a WebSocket agent learns the replacement of a rotated room as an HTTP one does, and a rotated room is retained exactly as long as an expired one (relay protocol spec O-05, O-08, O-47, O-48, O-49). Several of these change what a peer sees, so review the items marked **Behavior change**.

- **Behavior change:** when a room expires, every ticket ends as `expired` instead of `revoked`. Each client socket gets a new `room.expired` frame (the shape of `session.revoked`, reason `ROOM_EXPIRED`) instead of a `session.revoked` with reason `ROOM_EXPIRED`, and its pending requests get −32056 `ROOM_EXPIRED` with `data: {roomId, roomEpoch}`, the error an HTTP request in flight already got, instead of −32001 `SESSION_INVALID`. The provider socket is still closed without a frame.
- **Behavior change:** session status reports a session of an expired room as `state: "expired"` (with `revokedAt` set to the expiry), not `revoked`, so `waitForPeerApproval` on an expired room throws `APPROVAL_EXPIRED` instead of `SESSION_REVOKED`.
- **Behavior change:** `PeerMcpSession` ends a session that gets `room.expired` with a `PeerMcpError` whose code is `ROOM_EXPIRED` (it rejects the session's pending requests with it), as it does with `ROOM_ROTATED` for `room.rotated`.
- **Behavior change:** join, reclaim, approval, both revoke routes and rotate answer an expired room the relay still retains with 410 `{error: "ROOM_EXPIRED", code: -32056, roomId, roomEpoch}`, after the rotated-room check. Before, they answered 404 `ROOM_NOT_FOUND` (reclaim: 404 `ROOM_EXPIRED`). Once the retention ends and the room is deleted, every lifecycle route and session status answer 404 `ROOM_NOT_FOUND`.
- **Behavior change:** a reclaim of a live room whose reconnect lease expired is 410 `{error: "ROOM_LEASE_EXPIRED", roomId, roomEpoch}` (no code), a name of its own. Before, it was 404 `ROOM_EXPIRED` like an expired room. The provider forgets the saved lease on this 410 as it did on the 404.
- **Behavior change:** join compares the room's expiry like every other route and the sweep (`expiresAt <= now`). A join in the millisecond the room expires gets 410 `ROOM_EXPIRED` and leaves the invite unused, instead of taking the invite for a ticket that is already expired. Join also checks the room in the same order as the other lifecycle routes.
- **Behavior change:** the relay carries out a room's expiry wherever it finds the room expired first, not only in the sweep: the room check of a lifecycle or MCP route, ticket resolution, a WebSocket upgrade, a frame from one of the room's sockets, and a waiting `register` evaluation. Before, ticket resolution only marked the room `expired`, which made the sweep skip it, so its tickets were never ended and its requests in flight timed out (`MCP_REQUEST_TIMEOUT`) instead of getting `ROOM_EXPIRED`; a frame that found the room expired only closed its own socket.
- **Behavior change:** the `room.rotated` frame a rotation sends each client socket carries the replacement room: `rotatedTo` and `payload.replacementRoomId`/`payload.replacementRoomEpoch`. The socket's pending requests get −32057 `ROOM_ROTATED` with `data: {replacementRoomId, roomId, roomEpoch}`, as HTTP requests in flight do, instead of no data. The rotate route no longer has a loop that sent a second `room.rotated` to client sockets it had already closed (it reached none).
- A rotated room is retained until its original `expiresAt` plus 24 hours (`metadataRetainUntil`), as an expired room is, answering 410 `ROOM_ROTATED` with its replacement until then. This was already the behavior; the `RoomEntry.rotatedRetainUntil` member, which never had an effect, is removed.
- Protected relay API: `closeClientTicket` takes the new ticket end status `expired`; `roomClosedRpcError(entry, reason, status)` is replaced by `ticketClosedRpcError(entry, status)`, which also gives a rejection's and a revocation's error; `failPendingForSocket` sends the error's `data`; new protected `sendRoomExpired`, `expireRoom` and `expireRoomIfDue`. `checkLifecycleRoom` now also serves join and reclaim.
