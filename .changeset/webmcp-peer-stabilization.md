Stop forged relay control frames and publish-key guessing in `WebMcpPeerServer`, make durable files and catalog hashes deterministic, and return validated MCP results. Review the items marked **behavior change** when upgrading.

- Client sockets of `WebMcpPeerServer` relay only `mcp` frames and, once the client is approved, `offer` frames, stamped with `from: 'client'` and the relay's `sessionId`; other client frames are dropped. An unapproved client could previously send `session.revoked`, `room.rotated` or `approval.request` frames to the provider.
- Failed `POST /p` publish attempts share one rate-limit bucket per address (`authorizePublishRequest` returns `tokenHash: 'unauthenticated'`), so guessing keys is throttled. `InMemoryPublishRateLimitStore` keeps at most 4096 keys, and a room `ttlMs` is clamped to `[60 s, maxRoomTtlMs]` (new option, default 24 hours) on `POST /p` and on rotate.
- **Behavior change:** `readDurableJsonLinesSync(filePath, errorCode, schema, options?)` requires a row schema (`DurableJsonRowSchema<T>`) and validates every row, throwing `<errorCode>: row N` (`empty row N`, or `truncated final row` for an unterminated last row) with the cause. The `ignoreUnterminatedTail` option and `truncateUnterminatedTailSync` are added, and `FileAiRunLedgerStore` skips and truncates a torn final row instead of becoming unreadable.
- **Behavior change:** `hashDeploymentCatalog`, the room `catalogHash` and `hashTools` order tools by UTF-16 code units instead of `localeCompare`, so client and relay hashes agree on every locale. Catalogs with mixed-case names or names with `-`, `_` or digits hash differently, so regenerate any pinned `/mcp/catalog/:hash` URL or deployment `catalogHash` once. A restored `PeerMcpCatalogCache` is re-hashed.
- **Behavior change:** `new WebMcpPeerServer()` no longer parses `process.argv` or loads `.env.local`/`.env` files into `process.env`. A CLI entry point passes `argv: process.argv.slice(2)` and `loadEnvFiles: true` (and optionally `cwd`); flags given through `argv` still take precedence over constructor options. Environment variables are still read.
- **Behavior change:** the provider answers `tools/call` with an MCP `CallToolResult`. A host `CallToolResult` keeps its `content` and `isError`; other values get `structuredContent` and a text block with up to 16 KiB of JSON. A reply above the relay's 256 KiB message limit (`PEER_RELAY_MAX_MESSAGE_BYTES`) becomes a `RESULT_TOO_LARGE` error. `PeerMcpSession.request()` returns `PeerMcpRpcResponse`, and `callTool()` returns a validated `PeerMcpCallToolResult` or throws `INVALID_TOOL_RESULT`. At 128 live AI runs, `AiRunController.begin()` evicts finished, then idle runs, and throws the new `AiRunLimitExceededError` when all are busy, where later traced calls used to time out.
- When a provider socket reattaches, the relay sends `approval.restored` frames for approved, unexpired tickets, and the provider restores those sessions instead of answering `CLIENT_APPROVAL_REQUIRED`. Auto-reconnect retries with backoff, a relay `CATALOG_INVALID` error shows in `getSession().error`, in-flight HTTP `tools/call` requests are answered with `ROOM_ROTATED`, `SESSION_INVALID` or `ROOM_EXPIRED` when the room closes, and revoke responses report `alreadyRevoked` correctly.
- `PeerMcpSession.revoke()` works without a relay-issued session id, requests sent while the WebSocket connects wait for it, `fetchPeerServerConfig` rejects an already-aborted signal, and `redactInvitationUrl` no longer throws on malformed percent-encoding. New option `PeerMcpSessionOptions.fetchImpl`. New exports: `PeerMcpRpcResponse`, `PeerMcpContentBlock`, `PeerMcpCallToolResult`, `PeerMcpCatalogCache`, `PeerClientTicket`, `AiRunLimitExceededError`, `truncateUnterminatedTailSync`, `DurableJsonRowSchema` and `ReadDurableJsonLinesOptions`, and `isSecurePeerTransport` and `redactInvitationUrl` from the root.
