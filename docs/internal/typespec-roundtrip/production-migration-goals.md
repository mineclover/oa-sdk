# TypeSpec Production Migration Goals

Status: G9-G14 and the production source-path switch are implemented. ADR-009 accepts TypeSpec-first schema authoring, and default schema validation/build/bundle commands now emit production OpenAPI artifacts from the production TypeSpec bundle. G15 tracks the remaining reviewed drift burn-down after the TypeSpec source switch.

This document extends the completed G1-G8 decision roadmap with production migration goals. It does not reopen the TypeSpec-first decision; it scopes the work required to make the accepted TypeSpec bundle production-authoritative.

## Scope

The migration covers:

1. A production-owned TypeSpec source layout separate from evidence fixtures.
2. Schema build wiring that can produce or verify the production OpenAPI artifact from the TypeSpec bundle.
3. Rollback gates that keep the OpenAPI/Definition Builder path available while TypeSpec output is authoritative.
4. Downstream validation for the consumers that depend on the production OpenAPI artifact.

Out of scope:

- Adding a new `oa-sdk.typespec-extensions` schema version without a separate vocabulary decision.
- Moving runtime-only OA SDK behavior into TypeSpec comments or unchecked metadata.
- Removing the OpenAPI/Definition Builder rollback path without a separate deprecation/removal decision.

## Current Production Surfaces

The active production schema path is TypeSpec based:

- `packages/schemas/package.json` owns `build:typespec`, `validate`, `build`, `bundle`, and `preview` as TypeSpec-backed default commands.
- Root `package.json` owns `schema:validate` and `schema:bundle`.
- The production source bundle lives under `packages/schemas/typespec/`.
- Generated artifacts are `packages/schemas/src/.merged.yaml`, `packages/schemas/src/.merged.3.1.yaml`, `packages/schemas/src/.merged.3.1.meta.json`, and `packages/schemas/dist/openapi.{yaml,json}`.
- The OpenAPI/Definition Builder rollback path remains explicit through `schema:validate:openapi`, `schema:bundle:openapi`, `schema:preview:openapi`, package-level `build:openapi` / `validate:openapi`, and the target commands `build:merged`, `build:merged:staging`, and `build:merged:production`.
- Source fragments live under `packages/schemas/src/domains`, `packages/schemas/src/fragments`, `packages/schemas/src/profiles`, and `packages/schemas/src/targets` for the rollback/reference path.
- Current TypeSpec evidence lives under `docs/internal/typespec-roundtrip/fixtures/authored-canonical-bundle/` and is regenerated by `pnpm typespec:create-canonical-fixture`.
- The accepted restored drift manifest is `packages/schemas/typespec/accepted-restored-drift.json`; it pins current TypeSpec-restored-vs-reference normalized value hashes until those differences are burned down or intentionally refreshed.

The migration must treat those OpenAPI artifacts as generated/verified outputs, not as new TypeSpec source files.

## Goal Roadmap

| Goal | Purpose | Depends on | Done when |
|---|---|---|---|
| G9 Production TypeSpec source layout | Move from fixture-only evidence to a production-owned TypeSpec bundle location and ownership rule. | G8 and the accepted canonical fixture. | A production bundle directory, manifest, expected OpenAPI policy, and ownership note exist; the canonical evidence fixture remains a reproducible reference, not the production source. |
| G10 Schema build wiring | Connect the schema build or validation path to TypeSpec compile, OA SDK extension restore, expected diff, and OpenAPI 3.2 validation. | G9. | The selected schema command can validate the TypeSpec production bundle and either emits or verifies `packages/schemas/src/.merged.yaml` through the same bundle-check semantics. |
| G11 Rollback gate | Keep the OpenAPI/Definition Builder path green and reversible while the TypeSpec path is authoritative. | G10. | A documented rollback command or procedure restores the last green OpenAPI path, and CI or local gates prove both rollback and TypeSpec paths before removing any old source path. |
| G12 Downstream consumer gates | Prove parser, codegen, router, client, and mock-server behavior against the TypeSpec-derived production OpenAPI. | G10 and G11. | Focused downstream commands run against the TypeSpec-derived artifact, and the feature matrix lists the maintained commands before the migration is considered complete. |
| G13 Response wrapper projection drift burn-down | Decide and implement the policy for TypeSpec-emitted response body projection schemas versus the old inline response schema shape. | G10-G12 and `oa-sdk.typespec-extensions.v5`. | Implemented: response body projection artifacts were eliminated through inline body authoring and `accepted-restored-drift.json` no longer contains `component/added` entries. |
| G14 Component schema metadata parity | Burn down component-level schema differences that are not response wrapper projection artifacts. | G13 if it changes component shape; otherwise G10-G12. | Implemented: component-level `example`, property `example`, and `additionalProperties: false` metadata are authored in `.tsp`; `accepted-restored-drift.json` no longer contains component entries. |
| G15 Operation/path metadata parity | Burn down the remaining operation/path differences after response wrapper and component metadata decisions. | G13 and G14. | The `path/changed` set is eliminated or reduced to explicitly accepted operation/path metadata differences with stable gates and no downstream behavioral drift. |

## Recommended Production Layout

G9 should start from a production-owned bundle directory, separate from evidence fixtures:

```text
packages/schemas/typespec/
  README.md
  main.tsp
  tspconfig.yaml
  oa-sdk.typespec-bundle.json
  expected.openapi.yaml
  accepted-restored-drift.json
```

Initial population can use:

```bash
pnpm typespec:create-canonical-fixture -- --fixture-dir packages/schemas/typespec
```

That command is a bootstrap/rebase mechanism, not the default production build command. `docs/internal/typespec-roundtrip/fixtures/authored-canonical-bundle/` remains historical evidence and regeneration proof, while `packages/schemas/typespec/` is the production authoring source.

## Goal Boundaries

G9 should be a layout and ownership commit. It may copy or regenerate the accepted canonical bundle into a production-owned location, but it should not change the production schema command yet.

G10 should be the build wiring commit. It should preserve the explicit OpenAPI rollback path until the TypeSpec-derived output has an equivalent validation and expected diff gate.

G11 should be a rollback evidence commit. It should make the fallback path explicit enough that a failed TypeSpec migration can be repaired without guessing which file or command is authoritative.

G12 should be a downstream verification commit. It should avoid broad unrelated refactors and should focus on the consumers named by ADR-009.

G13-G15 should be independent drift burn-down commits. Each goal must update `packages/schemas/typespec/accepted-restored-drift.json` only after reviewing the normalized reference/restored values for the affected pointers. G13 and G14 are complete; G15 remains.

## Per-Goal Implementation Notes

### G9 - Production TypeSpec Source Layout

Status: implemented by `packages/schemas/typespec/`.

- Add the production bundle directory and a short README explaining that `.tsp` is the planned authoring source for the staged migration.
- Keep `oa-sdk.typespec-bundle.json` sidecar-less with `compatibility.oaSdkExtensionSchemaVersion: "oa-sdk.typespec-extensions.v5"` unless the migration discovers a real residual sidecar need.
- Keep `expected.openapi.yaml` bundle-local so G10 can compare TypeSpec-derived output without reading the old OpenAPI source as an oracle.
- Do not change `schema:validate`, `schema:bundle`, or `packages/schemas/src/.merged.yaml` ownership in G9.

### G10 - Schema Build Wiring

Status: implemented by `pnpm schema:typespec-check`, `pnpm schema:validate`, `pnpm schema:bundle`, and package-level `build:typespec`.

- Add a TypeSpec schema validation/build script before replacing existing `build:merged`; a first pass can be named explicitly, such as `schema:typespec-check` or an `@oa-sdk/schemas` package script.
- The new gate must run TypeSpec compile, OA SDK extension restore, expected diff, OpenAPI 3.2 validation, and sidecar or extension re-extraction stability.
- The gate must compare `packages/schemas/typespec/expected.openapi.yaml` with the reviewed reference using normalized OpenAPI diff so the TypeSpec bundle cannot drift silently.
- The gate must also compare the TypeSpec-restored artifact with the reviewed reference and require the exact accepted drift set plus pinned normalized reference/restored value hashes from `packages/schemas/typespec/accepted-restored-drift.json`.
- The accepted restored drift manifest blocks silent new drift after the source-path switch. It should burn down over time, but remaining drift is allowed only while hash-pinned and reviewed.
- Current reviewed restored-vs-reference drift is 22 entries: `path/changed=22`.
- Reusable component identity (`parameters`, shared responses, and operation usage refs) is restored through `oa-sdk.typespec-extensions.v5`.
- Response wrapper projection schemas were eliminated through inline response body authoring.
- Component schema metadata drift was eliminated through TypeSpec-native examples plus OpenAPI `@extension` metadata for singular examples and `additionalProperties: false`.
- Remaining drift burn-down target after the source-path switch is operation/path-level metadata differences. Do not refresh the manifest without reviewing the normalized value hashes.
- `schema:validate`, `schema:bundle`, `schema:preview`, and package-level `build` now depend on the TypeSpec-derived artifact.
- Preserve Definition Builder commands as the explicit rollback path until a separate removal decision.

### G11 - Rollback Gate

Status: implemented by `pnpm schema:rollback-check` and `pnpm --filter @oa-sdk/schemas run rollback:check`.

- Document the exact fallback command sequence for returning to the Definition Builder/OpenAPI path.
- Prove rollback by running the TypeSpec gate, restoring the OpenAPI path, and then running `pnpm schema:validate:openapi`.
- Keep generated artifacts clearly marked as generated so rollback does not turn `.merged.yaml` into a hand-edited source.

### G12 - Downstream Consumer Gates

Status: implemented by `pnpm schema:downstream-check` and `pnpm --filter @oa-sdk/schemas run downstream:check`.

- Run parser/codegen/router/client/mock-server checks against the TypeSpec-derived OpenAPI artifact, not only against the old `.merged.yaml`.
- Import the built `dist` exports for downstream packages, so the gate exercises package output rather than only source modules.
- Compile generated typegen, Hono router, Express router, and client TypeScript consumers so marker-only generation cannot pass with missing generated imports.
- Compile a synthetic webhook/header fixture as well as the production artifact so downstream features that are absent from the current production OpenAPI still stay guarded.
- Add or update focused commands in the feature matrix once the TypeSpec-derived artifact path is stable.
- Treat mock-server example selection as a required smoke surface because `dataValue` / `serializedValue` semantics motivated the extension vocabulary.

### G13 - Response Wrapper Projection Drift Burn-Down

Status: implemented.

- The production `.tsp` authors response-local list body schemas as anonymous `@body` model expressions, so TypeSpec emits inline OpenAPI response schemas for the three list endpoints.
- `Error._meta` is authored as an anonymous nested model, so TypeSpec no longer emits a standalone `ErrorMeta` component.
- The four previous `component/added` projection artifacts were removed from `accepted-restored-drift.json`.
- The resulting accepted drift after G13 was 36 entries: `path/changed=22` and `component/changed=14`.

### G14 - Component Schema Metadata Parity

Status: implemented.

- The 14 previous `component/changed` entries were classified as singular `example` parity, property-level singular `example` parity, or sealed-object `additionalProperties: false` parity.
- Models that need only singular OpenAPI `example` use `@extension("example", ...)`.
- Models that need both singular `example` and OpenAPI 3.2 `examples` keep `@example(...)` and add `@extension("example", ...)`.
- Property-level singular examples use `@extension("example", ...)` to avoid emitting an extra `examples` array.
- `AdminUsersExportRequest` and `PurgeUserRequest` author `additionalProperties: false` through `@extension("additionalProperties", false)`.
- The resulting accepted drift is 22 entries: `path/changed=22`.

### G15 - Operation/Path Metadata Parity

Status: planned.

- Current reviewed drift includes 22 `path/changed` entries.
- After G14, inspect only the remaining path entries and classify them by cause: parameter defaults such as explicit `required: false` / `explode: false`, operation object ordering-neutral normalization, or real metadata loss.
- Any operation/path metadata that affects parser, codegen, mock-server, router, or client behavior must be restored or covered by downstream tests before its hash can remain accepted.

## Completion Checklist

The production migration is complete only when:

- The production TypeSpec bundle is the documented schema authoring source.
- `packages/schemas/src/.merged.yaml` can be regenerated or verified from that bundle.
- The old OpenAPI path remains recoverable until removal is explicitly approved.
- `tsp-bundle-check --fail-on-breaking` passes for the production bundle.
- OA SDK OpenAPI 3.2 validation passes for emitted and restored output.
- Restored-vs-reference drift is eliminated or pinned in `packages/schemas/typespec/accepted-restored-drift.json` with reviewed normalized value hashes.
- Extension or sidecar re-extraction is stable with no missing expected entries, unexpected actual entries, or value mismatches.
- Downstream parser, codegen, router, client, generated TypeScript consumer compilation, synthetic webhook/header compilation, and mock-server gates are green against the TypeSpec-derived artifact.
